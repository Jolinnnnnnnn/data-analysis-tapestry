## Live model plug-in (not exercised here)
- Summaries and cards: `# === LIVE MODEL PLUG-IN POINT ===` in scripts/16_generate_summaries.py. It calls `claude-opus-5-5` with the facts JSON as the only user content, `fallbacks: "default"` (server-side refusal fallback, beta `server-side-fallback-2026-07-01`), `output_config.effort = "medium"`, and a JSON schema for cards. Every live output goes through the same validator; it gets one retry with the unmatched numbers listed, and otherwise the deterministic template is used and the attempt is logged.
- Ask: `# === LIVE MODEL PLUG-IN POINT (Ask) ===` in app.py. Claude returns `{template, params}` only.
- Not run in this session: there was no API key, and the venv's Python 3.9 can't install `anthropic` 1.x (the 0.x SDK works, with new request fields passed through `extra_body`).

## Prompting approach (for the deck)
- Rules decide what matters, Claude only words it, and code checks every number. The AI never computes, ranks or chooses alerts.
- The model works from a small, explicit facts payload per week or per card, which makes both writing and checking tractable (the summary sees ~30 values; each card sees ~10).
- Accuracy is enforced at three points: build time (the validator fails the build), render time (the app re-validates and blocks), and audit time (the trace re-reads every value from its upstream path).
- Where the AI's own checks caught its own errors: the template's rule thresholds (P19), the 4-dp rounding ties (P20), and a week index masquerading as a count (Iteration 5).
